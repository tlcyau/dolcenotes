# dolcenotes

A cross-platform handwritten note app for tutors, with one shared storage backend for tablet, phone and laptop.

## Why

Handwritten notes can already be used across devices today, but only by stitching together several apps and ecosystems (Samsung, Microsoft, …). dolcenotes aims to make the same notes available everywhere from a single app and a single store.

**Objective:** a handwritten note app that works cross-platform with the same storage.
**Target:** end of 2026.

## Scope

**Must have**

- Create handwritten notes
- View and edit handwritten notes from both tablet and laptop

**Nice to have**

- Attach notes to a specific client (student)
- Track client details and data: number of lessons paid for, outstanding payments, calendar

## Tech stack

| Layer | Technology | Hosting | Purpose | Status |
| --- | --- | --- | --- | --- |
| Mobile frontend | Expo (React Native), TypeScript, React Native Skia | Apple App Store / Google Play | Tutor mobile client and touchscreen canvas for handwritten lesson notes | Development |
| Web frontend | React, TypeScript, Tailwind CSS, shadcn/ui | Vercel / Cloudflare Pages | Tutor web portal for dashboard, scheduling and desktop note editing | Development |
| Backend API | Node.js, NestJS, TypeScript, Prisma ORM, Zod/tRPC | Kubernetes pods (AWS EKS) | Core API, business logic, route handlers and end-to-end type contracts | Development |
| Primary database | PostgreSQL (with JSONB) | Supabase | Relational storage for tutors, students, lessons and raw vector note path JSON | Development |
| Cache & queue | Redis 7, BullMQ | AWS ElastiCache | Background jobs: PDF rendering, handwriting OCR, notifications | Planned |
| Object storage | AWS S3 / Cloudflare R2 (MinIO locally) | AWS / Cloudflare | Pre-rendered PNG/PDF note exports and preview thumbnails | Planned |
| Containers & orchestration | Docker, Docker Compose, Kubernetes | Local dev / AWS EKS | Local Postgres, Redis and MinIO; production pod deployment | Stable |

### Note storage

Handwritten notes use a dual-storage strategy:

- **PostgreSQL `JSONB`** holds the raw vector stroke paths. This is the source of truth and what the editors load.
- **S3 / R2** holds pre-rendered PNG/PDF exports and thumbnails for quick previews, generated by background jobs.

## Repository layout

This is a Turborepo monorepo managed with Yarn 4 workspaces.

```
apps/
  mobile/   Expo (React Native) app
  web/      TanStack Start + Vite web portal
packages/
  db/       Prisma schema, migrations and client (@workspace/db)
  ui/       Shared shadcn/ui components (@workspace/ui)
```

## Getting started

Requires Node.js 20 or later and Yarn 4 (via Corepack).

```bash
corepack enable
yarn install
yarn dev          # run all apps in dev mode (web on http://localhost:3000)
```

Other root scripts, all run through Turbo:

```bash
yarn build
yarn lint
yarn format
yarn typecheck
```

### Database

The database is hosted on Supabase. Prisma lives in `packages/db`.

```bash
cp packages/db/.env.example packages/db/.env   # then fill in your Supabase connection strings
yarn db:push      # sync the schema to the database (no migrations yet)
yarn db:studio    # browse data in Prisma Studio
```

Get both connection strings from the Supabase dashboard under **Connect → ORMs → Prisma**:

- `DATABASE_URL`: the transaction pooler (port `6543`), used by the app at runtime.
- `DIRECT_URL`: the session pooler (port `5432`), used by the Prisma CLI.

To work against a local database instead, run `yarn db:up` (Docker) and point both variables at `postgresql://dolcenotes:dolcenotes@localhost:5432/dolcenotes`.

The Prisma client is generated into `packages/db/src/generated` (git-ignored) and is regenerated automatically before `dev`, `build` and `typecheck`. Use it from other workspaces:

```ts
import { createPrismaClient } from "@workspace/db";

const prisma = createPrismaClient();
const notes = await prisma.note.findMany();
```

### Adding UI components

shadcn/ui components live in the shared `ui` package. To add one, run from the repo root:

```bash
yarn dlx shadcn@latest add button -c apps/web
```

This places the component in `packages/ui/src/components`. Import it from the `ui` package:

```tsx
import { Button } from "@workspace/ui/components/button";
```
